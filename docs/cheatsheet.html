qSFC cheat sheet

One element per line. Keywords are case-insensitive. Indentation is cosmetic. Full rules: docs/SPEC.md.

Elements

sfc nameheader: starts an SFC routine (optional for the first one)
init nameinitial step (exactly one)
step name 5s "desc"step; preset and description optional
valve [:=] 1;action: ST lines under the step (N; qualifiers below)
-- start_btntransition (auto-named T1, T2…)
-- go: a AND bnamed transition
-- done -> idlejump to a step
tag n : DINT "desc"optional type/description override
// commentcomment (kept in actions, dropped elsewhere)

Durations

500ms 5s 2m 1h 1m30s — a unit is required.

Step members

fill.Xstep active
fill.FSfirst scan of the step
fill.DNtimer reached the preset
fill.Ttime active (ms)

Exported as Step_001.DN etc.

Assignments in actions

x [:=] 1;non-retentive: back to 0 when the step ends
x := 1;retentive: stays until written again
on a, bsugar for a [:=] 1; b [:=] 1;
set asugar for a := 1;
reset a, bsugar for a := 0; b := 0;

A sugar line is only the keyword and tag names (comma-separated), an optional ; and comment. The tags are BOOL.

Actions and qualifiers

step fill
  on valve          // N: lines before any qualifier
  S
    alarm := 1;
  L 10s
    horn [:=] 1;
Nnon-stored: while the step is active
Sstored: keeps running after the step, until reset
Rresets a stored action
L 10stime limited: while active, at most 10 s
D 2stime delayed: starts after 2 s if still active
Ppulse: once, when the step becomes active

A line holding only the qualifier (and its duration) starts an action; its ST goes on the lines below. L and D need a duration, the others take none.

Selection (OR): one leg runs

step check
select
  -- ok
  step pack
  -- pack_done
|
  -- NOT ok
  step reject
  -- rejected -> idle
end
step next

After a step. Legs start and end with a transition. Continuing legs merge into the step after end.

Parallel (AND): all legs run

-- go
parallel
  step fill_a
|
  step fill_b
end
-- level_a AND level_b

After a transition. Legs start and end with a step. A transition follows end.

Several routines

program tank          // optional, before the routines
st main               // first routine = main
  call fill_seq;      // exported as JSR(fill_seq,0);
  call alarms;
sfc fill_seq
init idle
-- start_btn
step fill 5s
-- fill.DN -> idle
st alarms
  alarm := level_high AND NOT valve;
  • A routine runs to the next sfc/st line. Tags and names are shared by the whole file.
  • call works in ST routines and in actions, not in conditions. JSR(name, 0); works too.
  • Jumps stay inside their SFC routine; read another routine's step with fill.X.

Rules to remember

  • Steps and transitions alternate. A select block counts as a transition, a parallel block as a step.
  • Names: letter or _ first, max 40 chars, no __, no trailing _. Steps, transitions and tags share one namespace.
  • After a jump the flow stops: the next line starts a new chain (a step reached by a jump).
  • Inside a branch, a jump can only end a select leg. Jumps can't enter or leave a parallel.
  • Tags are created automatically: BOOL by default, DINT/REAL inferred from numbers.
  • A chart may end on a step (warning W300).

Complete example

sfc tank
init idle
  motor := 0;
-- start: start_btn AND safety_ok
step fill 5s "Fill the tank"
  valve [:=] 1;
-- fill.DN
step drain
  pump [:=] 1;
-- level_low -> idle
