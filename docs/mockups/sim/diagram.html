Phase 4e · The diagram while simulating

The same chart in three versions. State: fill is active (3.1 s of 5 s), so its transition fill.done OR level_high can fire; level_high just came on, so it is true (✓). Hover a transition or an input in B and C.

  1. Click a transition's bar: it fires on the next scan, whatever its condition, if a step before it is active (otherwise a tip says which step must be active). The Trace notes "fired by hand".
  2. Click an input in a condition (a tag the chart only reads): it toggles, like in Live tags. A number opens a small field. Shift+click: a pulse (1 for one scan), for push buttons.
  3. Colors: every part of every condition is green or red, all the time, not only for the transitions that can fire; a part is a tag, a step member (fill.done) or a comparison (count < 10). The bar shows the transition: green / red when it can fire, gray when its step isn't active.

A · Colored parts

Every part of a condition is green (true) or red (false): tags, step members (fill.done) and comparisons (count < 10) as one unit; AND / OR / NOT and brackets stay gray. ✓ / ✗ after a condition that can fire now. Clicks work as in B and C, without a visual cue.

B · Input buttons

A's colors, and every input in a condition is a button: filled green when 1, outlined red when 0; click it to toggle. A transition that can fire has a ring on hover: click its bar to fire it.

C · Buttons and values

B, and a comparison shows its tag's value under it (count=7) with a green or red underline, so you see why it is true or false.
