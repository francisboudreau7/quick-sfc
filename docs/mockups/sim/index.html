Phase 4e · Simulation (mockup)

The chart runs like the PLC: each scan runs the active steps' actions, then fires the true transitions once; a step that ends gets a last scan that resets its [:=] outputs. Play runs in real time, Step runs one scan. Real diagram, highlighting and S/T column; values are static here.

  1. Simulate (button in the menu bar, or F5) switches the window to simulation: the editor is read-only (editing stops the simulation), the Tags panel becomes Live tags, and a Trace tab joins Problems.
  2. Inputs are the tags the chart only reads: click to toggle a BOOL, type a number. Outputs show as lamps (with "stored" for set / S). Steps list their time.
  3. Diagram: active steps filled green, the transitions after them green when true and red when false, a timer badge on an active step with a preset. The editor highlights the active step's line and its action lines; routine tabs show a dot when a routine has an active step.
  4. Minimal ST (as chosen): expressions, := / [:=], IF / ELSIF / ELSE, the sugar, step members and the qualifiers N S R L D P. Anything else (TON, CASE, JSR into ladder…) is skipped with a note in the Trace.
  5. Help playgrounds get a Run button: the same simulation, with the inputs as toggles under the code.
  6. -- else as the last leg of a select: true when every other leg is false; exported as NOT (c1 OR c2 …), drawn with its condition written out.
  7. Logic checks (W700-W704) in Problems while you type, table below.

C · SFC logic checks (warnings in Problems)

W700legs 1 and 2 of this select can both be true (when ok AND big): the first one wins
Fix: write the second leg -- else, or -- big AND NOT ok
select
  -- ok
  …
|
  -- big
  …
end
W701valve is written in two parallel legs (lines 8 and 14): the last one written wins each scan
Fix: write it in one leg only
parallel
  step fill_a
    on valve
|
  step fill_b
    valve [:=] 0;
end
