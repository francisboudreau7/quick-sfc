# Studio 5000 import test pack — Phase 1

Each `.L5X` here was generated by `qsfc export` from the `.qsfc` file of the same name. The goal is to confirm in **one session** that Studio 5000 accepts everything Phase 1 produces, and to settle the points marked **[Verify]** in docs/SPEC.md.

Per chart, there are three files:
- `tpNN_*.qsfc`: the source
- `tpNN_*.L5X`: the file to import
- `tpNN_*.diagram.txt`: the expected diagram, drawn by `qsfc show` from **the same layout as the L5X coordinates**, so Studio's picture should have the same shape. The text view writes jumps as `→ target` labels and doesn't draw automatic convergence bars; Studio draws real wires and bars there. Open it in Notepad with a monospace font.

## Before you start

- ⚠️ **Save the project before every import.** A bad L5X can crash Studio 5000 instead of showing an error (this happened once before; see L5X_GUIDE.md §9).
- Use any project with a CompactLogix controller (v32.01 if possible; note the version you used).
- **How to import:** in the Controller Organizer, right-click **MainTask** → **Add** → **Import Program...** → choose the `.L5X` → **OK** in the Import Configuration dialog (accept the defaults).
- Each file is a separate Program named like its routine (`tp01_linear`, ...), so you can import them all into the same project one after the other.

## What to report for each file

Copy this block per file into your reply (or just "OK" when everything matched):

```
tpNN: import OK / error

  diagram matches the description below: yes / no (what differs)

```

A photo or screenshot of each opened SFC routine is the most useful thing you can send me.

## Things to check in every file

1. **Import** finishes without errors. Warnings are fine, but note them.
2. **Verify** the program: right-click the program → **Verify** (or *Logic → Verify → Controller*). Expect **0 errors**.
3. **Main routine:** Program Properties → Configuration shows the SFC routine as **Main**.
4. **Element names [Verify]:** these files carry each step's name in **two places**, so you can tell me which one you prefer to see:
   - **a. Tag description:** the qSFC name (`idle`, `fill`, ...) should appear as the step's **description** next to the box, and in the description column of tag `Step_000` in the program tags. Report whether it shows **beside the box**, **only in the tag list**, or **not at all**. Transitions get their name (`start`, `T1`, ...) the same way.
   - **b. Action comment:** every step's action starts with `// idle` (or `// fill - Fill the tank` when there is a description). Steps that had no action now have an action containing only that comment. Check that Verify accepts these comment-only actions.
   - Then tell me: keep **a**, **b**, or **both**?
5. **Layout:** no boxes on top of each other and no wires crossing boxes. The layout doesn't need to be pretty, only readable.
